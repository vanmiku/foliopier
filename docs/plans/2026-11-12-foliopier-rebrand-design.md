# FolioPier AI brand design

The product name is **FolioPier AI**. The selected future website domain is **foliopier.com**; registration and deployment are not part of this change. Existing installation and support links must remain usable.

The user preferred the first abstract-AI and paper-companion concepts after comparing five rounds. Use the original orange abstract mark as the main identity. Use the rounded folded-paper companion, close to B1, as secondary welcome artwork. Rebuild both as deterministic flat SVG assets with clear monochrome forms, rather than using generated presentation boards as application icons.

The brand should feel clear, approachable and practical. Keep the current reading layout and existing light/dark behavior. Update the mark, product name and selected accent tokens; do not redesign the article/session interaction. New brand text must fit narrow navigation and retain accessible contrast.

Public presentation includes the application shell, browser titles, installable web-app metadata, notifications, public shares/PDF credits, welcome content, English/Chinese README and documentation, and GitHub repository name/About/topics. Marketing screenshots use isolated synthetic data, not the owner's documents or conversations. Describe existing features and platform/account limitations accurately.

Expose `foliopier` as the primary command and retain `mydash` as a backwards-compatible command. Preserve existing storage, configuration, protocol headers, cookies, browser storage, service IDs, Agent hook markers and installed permissions. Do not globally replace these identifiers or rewrite user-authored historical documents. Old repository Git URLs must continue to reach the same repository after a rename. Keep copyright and historical release records truthful.

Prepare a backwards-compatible patch release, **0.3.1**, so new installers and existing users receive the brand and command changes together. Keep package/lock/changelog consistent. Merge only the verified head after all required CI groups pass. Let the existing main workflow publish the stable tag and Release. Test updating through the old remote URL and confirm installed files, configuration and data are preserved.
